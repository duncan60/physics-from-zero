# 題目維護與每站總結複習 設計文件

日期：2026-10-21
狀態：已確認（Duncan：「直接讓我提案」，照 Claude 的提案執行）
前面的設計：`2026-10-19-physics-from-zero-design.md`、`2026-10-20-variety-and-game-design.md`（目標、非目標、反目標全部仍然有效）

## 1. 為什麼要做

- 網站是公開的，題目一定會有錯字或說不清楚的地方，學習者需要一個管道告訴我們。
- 現在新增一課要改三個地方（課程檔、`stations.ts`、測試裡寫死的清單），很容易漏。
- 想檢查某一題長怎樣，得從頭一路點過去。
- Duncan 學完一站後覺得「還有些模糊」，需要一份整站的重點整理，加上混合整站內容的複習題，確認自己真的學會。

## 2. 範圍

### 這次要做

1. **回報問題連結**：每一步（觀念卡、題目、動畫、配對）下方都有小連結「回報問題」，在新分頁打開 GitHub 的新增 issue 頁面，標題與內容預先填好課程 id、步驟 id、題型與網站版本頁面網址。網址只帶這些識別資料，不帶任何個人資料。連結旁有一行小字「需要 GitHub 帳號」。預填的 label 是「題目回報」（上線時在 repo 建立這個 label）。
2. **新增一課只改一個檔案**：用 Vite 的 `import.meta.glob` 自動讀取 `src/content/lessons/*.ts`。檔名格式 `站-課-英文名稱.ts`（例如 `2-3-action-reaction.ts`），檔名開頭必須等於課程 id。課程依站、依課號排序。`stations.ts` 只保留各站的標題。測試改成自動驗證：檔名與 id 一致、每站課號從 1 開始連續不跳號、id 不重複；刪除測試裡寫死的課程清單（但保留「第 1 站和第 2 站的現有課程都在」這類不會隨新增課程而壞掉的檢查可以接受）。README 的「新增一課」說明跟著更新。
3. **本機預覽頁**：只在開發模式（`import.meta.env.DEV`）出現的路由 `#/preview`。列出每一站、每一課、每一步（顯示步驟 id 與題型）；點一下就從那一步開始上課，不受解鎖限制，完成或離開都不會存進度，也不加 XP。正式建置的網站沒有這個路由（打開 `#/preview` 視為找不到頁面，回地圖）。
4. **每站重點總結與複習**：
   - **內容**：每站一個總結檔 `src/content/reviews/站號-英文名稱.ts`（同樣自動讀取），包含：3 到 6 個重點（每個 ≤ 60 字元）、公式表（名稱與公式）、常見陷阱（「錯的想法」與「正確的想法」成對，優先使用 Duncan 上課時真的犯過的錯）、5 到 8 題複習題（使用現有的所有題型，混合整站各課的觀念，至少用到兩種題型）。
   - **進入點**：完成一站的最後一課時，完成畫面多一個按鈕「看本站重點」；路線地圖上每站的最後一個節點是「本站重點與複習」，該站所有課程都完成才解鎖。
   - **流程**：總結頁（重點、公式表、常見陷阱）→ 按「開始複習」→ 複習題（沿用上課流程，答錯回饋、引導、看解答、Combo、音效、完成成績、完美都一樣）→ 完成畫面。總結頁也可以直接回地圖，不一定要做複習。
   - **進度**：複習的 id 是 `review-站號`（例如 `review-1`），完成與完美記在既有的 `completed`／`perfect` 清單裡，不需要改存檔版本。地圖節點：未解鎖（鎖）、可以做、已完成（勾）、完美（金色星星），和課程節點同一套狀態規則。
   - **不擋路**：複習不影響下一站的解鎖。
   - **這次的內容**：第 1 站（1-1～1-5）與第 2 站（2-1～2-4）的總結與複習題。內容來自已上線的課程與上課紀錄 `.superpowers/tutoring-log.md`。
5. **上一批留下的小修正**：
   - 拼算式第 2 步答錯並走完「一步一步來」回到原題時，保留已經拼對的算式，直接回到第 2 步（不用重拼）。
   - 手機 390px 寬、XP 三位數、連續天數兩位數時，頁首仍維持一行。
   - 1-5 `bus-slide` 第 2 步數值 5 的回饋不再引用「(10 + 0) ÷ 2」。

### 不做

- 站內的總結以外，不做「整個網站的總複習」。
- 不做線上表單或後端來收回報；只用 GitHub issue。
- 不改存檔版本。

## 3. 限制

- 沿用現有技術，不加執行期依賴。
- 介面文字繁體中文（台灣），不用 emoji；360px 不得水平捲軸；可點的東西 ≥ 44px（回報連結本身是次要連結，但點擊範圍仍要 ≥ 44px 高）；淺色深色；尊重減少動態效果。
- 正式網站的 bundle 不能包含預覽頁（用 `import.meta.env.DEV` 條件，讓建置時被移除）。
- 回報連結用 `target="_blank" rel="noopener noreferrer"`。

## 4. 留給實作者決定

- 預填 issue 的文字格式（必須包含課程 id、步驟 id、題型、可以點的網址）。
- 總結頁的版面與樣式。
- 自動讀取時課程檔的匯出方式（例如預設匯出，或固定名稱的具名匯出），只要 README 寫清楚。
